적용 우선순위

기본기: 1, 2, 5, 10 (명명, 단일책임, 에러처리, 주석)
구조화: 3, 7, 13, 17 (중첩방지, 매개변수, 추상화)
품질: 9, 12, 18, 20 (중복제거, 테스트, 방어적프로그래밍, 리팩토링)
고급: 4, 8, 14, 16 (불변성, 전역상태, 응집도, 예측가능성)

1. 명확하고 의미 있는 이름 사용하기
룰: 변수, 함수, 클래스명은 그 목적과 역할을 명확히 드러내야 한다.

❌ d, temp, data, info
✅ userAge, calculateTotalPrice(), DatabaseConnection
약어보다는 전체 단어를 사용하고, 문맥에서 의미가 명확해야 함

2. 함수는 단일 책임만 가져야 한다
룰: 하나의 함수는 하나의 명확한 작업만 수행해야 한다.

함수명이 "and", "or"를 포함한다면 분리를 고려
함수 길이는 20-30줄을 넘지 않도록 권장
하나의 추상화 레벨에서만 작업

3. 깊은 중첩을 피하라
룰: 중첩 깊이는 3레벨을 초과하지 않도록 한다.

Early return 패턴 사용
Guard clauses 활용
복잡한 조건문은 별도 함수로 추출

4. 불변성을 선호하라
룰: 가능한 한 불변 객체와 데이터를 사용한다.

const 키워드 우선 사용
객체 수정 대신 새 객체 생성
부작용(side effect) 최소화

5. 명시적 에러 처리
룰: 모든 에러 상황을 명시적으로 처리하고 문서화한다.

예외를 무시하지 않기
구체적인 예외 타입 사용
에러 메시지는 문제 해결에 도움이 되도록 작성

6. 매직 넘버와 매직 스트링 금지
룰: 하드코딩된 숫자나 문자열 대신 명명된 상수를 사용한다.

❌ if (status == 200)
✅ if (status == HTTP_OK)
설정값은 별도 파일이나 상수로 관리

7. 함수 매개변수는 3개 이하로 제한
룰: 함수의 매개변수가 3개를 초과하면 객체나 구조체로 그룹화한다.

매개변수가 많으면 함수가 너무 많은 일을 하는 신호
관련된 매개변수는 객체로 묶기
선택적 매개변수는 기본값 설정

8. 전역 상태 최소화
룰: 전역 변수와 공유 상태를 최대한 피한다.

의존성 주입(Dependency Injection) 사용
상태는 가능한 한 지역적으로 관리
싱글톤 패턴 사용 최소화

9. 코드 중복 제거 (DRY 원칙)
룡: 동일한 로직이 두 번 이상 나타나면 공통 함수로 추출한다.

3번 규칙: 같은 코드가 3번 나타나면 리팩토링
단, 우연한 중복과 진짜 중복 구분하기
추상화 레벨 일치시키기

10. 주석보다는 자명한 코드 작성
룰: 코드 자체가 문서가 되도록 작성하고, 주석은 "왜"에 집중한다.

"무엇을" 하는지는 코드로, "왜" 하는지는 주석으로
주석은 최신 상태 유지
잘못된 주석은 주석 없음보다 나쁨

11. 일관된 코딩 스타일 유지
룰: 팀 전체가 동일한 코딩 컨벤션을 따른다.

들여쓰기, 괄호 위치, 네이밍 규칙 통일
자동 포매터 도구 사용
코드 리뷰에서 스타일 검토

12. 테스트 가능한 코드 작성
룰: 모든 함수와 클래스는 독립적으로 테스트 가능해야 한다.

외부 의존성 분리
순수 함수 선호
Mock과 Stub 활용 가능한 구조

13. 인터페이스와 구현 분리
룰: 추상화를 통해 구체적인 구현에 의존하지 않도록 한다.

의존성 역전 원칙(DIP) 적용
인터페이스 우선 설계
구현체는 교체 가능하도록 설계

14. 데이터와 동작의 응집도 높이기
룰: 관련된 데이터와 그 데이터를 조작하는 함수를 함께 배치한다.

객체지향에서는 클래스 내부에
함수형에서는 모듈 단위로
데이터 은닉(encapsulation) 원칙 적용

15. 조기 최적화 금지
룰: 성능 최적화는 측정 후에 실제 병목점에서만 수행한다.

가독성을 희생하면서 미리 최적화하지 않기
프로파일링 도구로 실제 성능 측정
알고리즘 복잡도가 더 중요

16. 예측 가능한 동작 보장
룰: 함수는 동일한 입력에 대해 항상 동일한 결과를 반환해야 한다.

순수 함수 선호
숨겨진 의존성 제거
예상치 못한 부작용 방지

17. 적절한 추상화 레벨 유지
룰: 하나의 함수나 모듈 내에서는 동일한 추상화 레벨을 유지한다.

고수준 개념과 저수준 구현 분리
계층적 구조로 코드 조직화
세부사항은 하위 레벨로 위임

18. 방어적 프로그래밍 실천
룰: 입력값 검증과 예외 상황에 대한 대비를 철저히 한다.

널 체크와 경계값 검증
전제 조건(precondition) 확인
실패 시 안전한 기본값 제공

19. 코드 리뷰 활용
룰: 모든 코드 변경사항은 동료의 리뷰를 거쳐야 한다.

버그 조기 발견
지식 공유와 학습 기회
코드 품질 표준 유지

20. 지속적 리팩토링
룰: 코드는 지속적으로 개선되어야 하는 살아있는 문서다.

작은 단위로 자주 리팩토링
테스트 코드로 안전망 확보
코드 냄새(code smell) 즉시 제거
